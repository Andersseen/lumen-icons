# Spec: Refine navigation motion and pin the icon controls

- **Status:** in-progress
- **Date:** 2026-08-18
- **Author:** Codex session, maintainer-directed
- **Semver impact:** patch — visual animation fixes and demo layout behavior; no public API changes

## Summary

Make the `/icons` desktop control sidebar reliably sticky below the app header. Replace generic rotating navigation motion with directional, per-shape motion for the visible `arrow-uturn-*` and `bars-*` families.

## Motivation

Direction arrows communicate a route, not a rotation. Likewise, a hamburger/list icon should organize its lines rather than morph into an unrelated X. The catalog sidebar must remain available while reviewing many icons.

## Scope

**In scope:**

- Sticky desktop host for `app-icons-sidebar` on `/icons`.
- Dedicated route-draw motion for `arrow-uturn-down/left/right/up`.
- Staggered line-entry motion for `bars-2`, `bars-3`, `bars-3-*`, and `bars-4`.
- Directional list-and-arrow motion for `bars-arrow-down` and `bars-arrow-up`.
- Regenerated icon components, changelog and AI state.

**Out of scope:**

- Changing the icon API, SVG sources, mobile controls, or unrelated navigation families.

## Design

- Put the responsive sticky layout classes on the sidebar component host; its inner `<aside>` only carries semantics and width.
- `uturn-draw` splits the outline into route and arrowhead sections, revealing the U route to its tip; filled settles once without rotation.
- `bars-stagger` retains each line’s alignment but reveals lines from their anchored edge in a short cascade.
- `bars-arrow` reveals the list lines first, then the direction arrow travels into its final position.
