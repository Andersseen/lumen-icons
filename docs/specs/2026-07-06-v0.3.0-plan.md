# Plan: lumen-icons 0.3.0 (minor) + demo refresh

- **Status:** draft
- **Date:** 2026-07-06
- **Author:** Claude (audit session) — pending maintainer approval
- **Type:** umbrella release plan. Each P0/P1 item becomes its own spec (or is small enough to skip one per `docs/specs/README.md` rules) and its own PR.

## Summary

Ship `lumen-icons@0.3.0` with two consumer-facing features (free-form `size`, hover-triggered animations), close the release-blocking OSS hygiene gaps (root LICENSE, external package validation), and refresh the demo (SEO/prerender, playground parity). Ordered by urgency; P0+P1 are the release, P2 lands with or right after it, P3 is explicitly deferred.

## Audit findings this plan is based on (verified 2026-07-06)

- ✅ Already healthy: all 362 icons have metadata + resolved animations; demo docs API table covers all 12 inputs; CI runs lint/typecheck/build/publint/unit/e2e with preview+prod deploys; contract spec guards against `angular-movement` leaking into the lib.
- ❌ **No root `LICENSE`** — GitHub shows the repo as unlicensed (`packages/icons/LICENSE` exists, root doesn't). Adoption blocker for an OSS library.
- ❌ `LmnIconSize` is a closed union (`12|14|16|20|24|32`) — consumers cannot render 18/28/48 px icons without CSS hacks.
- ❌ Animations only trigger on mount (`animate` input). No hover trigger — the most common icon-animation use case (Lucide-style) is unsupported.
- ❌ `vite.config.ts` has `prerender.routes: []` — `/`, `/icons`, `/docs` ship as a blank-shell SPA; near-zero SEO for the marketing site.
- ❌ Milestone "validate published package in a fresh external app" (architecture-plan.md #1) still pending — publint can't catch runtime/APF integration issues.
- ⚠️ All 324 Heroicons outline are already generated (362 = 324 + 38 custom) — **there is no free icon growth left from the current source**; icon-count growth needs a decision (out of scope here).
- ⚠️ Playground exposes 9 of 12 inputs — no free-text `color` / `backgroundColor` pickers.
- ⚠️ `CLAUDE.md` drift: omits `tone`/`backgroundTone`/`backgroundColor`/`padding`/`radius` inputs and the `check:package` step.

## P1 — The 0.3.0 features (each gets a spec before coding)

### P1.1 Free-form `size` · minor · ~2–4 h
Widen `LmnIconSize` from the closed union to `number`, keeping `12|14|16|20|24|32` as documented presets. Type-widening on an input is non-breaking for consumers.
- Touch: `icon.types.ts`, docs API table, lib README, playground `size-picker` (add free-number input alongside presets).
- Acceptance: `<lmn-check [size]="18" />` compiles and renders 18×18; presets unchanged; `pnpm run check` green.
- Risk: none identified; the base class already binds `[attr.width]="size()"` verbatim.

### P1.2 `animateOnHover` input · minor · ~1–2 days (biggest item)
Pure-CSS hover trigger reusing the existing recipes: when `animateOnHover` is true, the recipe's animation runs on host `:hover` instead of on mount. Coexists with `animate` (mount). Only `loader` keeps `infinite`; hover animations run once per hover via the same keyframes.
- Touch: `LmnIconBase` (new input + host class `lmn-animate-hover`), `scripts/animations.mjs` (emit a `:hover` variant of each recipe's `animate` block), `scripts/generate-icons.mjs` if template changes, then **regenerate all 362 icons** (large mechanical diff, own commit).
- Demo: playground toggle (mount / hover / off), docs animations section update.
- Acceptance: hover replays the animation; `prefers-reduced-motion` disables it; `animate` behavior unchanged; no bundle-size regression for consumers not using it beyond the extra CSS block; contract spec still passes.
- Risk: CSS-only hover restart quirks (animation replays only after un-hover). Spec must settle this behavior explicitly before implementation.

### P1.3 Release 0.3.0 · ~1 h
Follow WORKFLOWS.md W6: version bump, CHANGELOG (move Unreleased), `publish:icons:dry-run` → inspect exports map → publish, re-run P0.2 validation against the published version, update STATE.md.

## P2 — Demo refresh (ship with or right after 0.3.0)

### P2.1 Prerender + SEO · ~2–4 h
Set `prerender.routes: ['/', '/icons', '/docs']`; add per-route `<title>`/meta description and OG tags; verify Cloudflare Pages serves the prerendered HTML.
**Done when:** `curl` of each route returns content-ful HTML (not the empty shell).

### P2.2 Playground parity · ~1–2 h
Add `color` and `backgroundColor` free-value pickers so all 12 inputs are demoable; copied code snippets include whatever is set.

### P2.3 Per-icon pages `/icons/[name]` · ~1–2 days · **optional, own spec**
Dynamic route with the icon rendered large, all-prop playground, copy blocks, and related icons; prerender all 362 routes for SEO (the Lucide model). Highest-value demo feature, but the only P2 item big enough to slip — cut it first if time-boxed.

---

## P3 — Deferred (post-0.3.0, tracked but not in this release)

- Release automation with Changesets (architecture-plan #3) — manual `publish:icons` flow is adequate at current cadence.
- Visual regression for the icon grid, light + dark (architecture-plan #4).
- E2E beyond Chromium (add webkit at least, for Safari CSS animation quirks).
- Icon-count growth strategy (new source set or curated custom batch) — needs a product decision; all Heroicons are exhausted.

## Suggested execution order

```
P0.1 → P0.3 → P1.1 → P0.2 (against 0.3.0-rc via pack) → P1.2 → P2.1 → P2.2 → P1.3 (publish) → P2.3
```

Rationale: P0.2 is most valuable run once against the build that already contains both API changes; P2.1/P2.2 are app-only and can't destabilize the package, so they ride along before the publish.
